# NUVEXA Post Studio

موقع محلي عربي لاستقبال بوستات Gemini من Gmail، فحص الصور، مراجعة وتعديل المحتوى، والنشر على صفحة Facebook بعد الموافقة اليدوية فقط.

## التشغيل على Windows

1. ثبّت Node.js 24 LTS أو إصدار أحدث (الحد الأدنى 22.13).
2. افتح `start.cmd` بالضغط مرتين. أول تشغيل يثبت الاعتمادات باستخدام `npm ci`.
3. افتح **http://127.0.0.1:3210**. اترك نافذة البرنامج مفتوحة للعمل في الخلفية. إغلاق تبويب المتصفح لا يوقف استقبال الإيميلات، لكن إغلاق البرنامج أو إطفاء الجهاز يوقفه.

بديل من PowerShell: `npm.cmd ci` ثم `npm.cmd start`.

`launch.ps1` يشغّل البرنامج مخفيًا في الخلفية (أو يستخدم النسخة الشغالة) ويفتح الموقع. يمكن استخدامه كهدف اختصار NUVEXA على Desktop. إغلاق المتصفح لا يوقف البرنامج.

## النسخة المشفرة من إعدادات الحسابات

`backup/account-settings.encrypted.json` يحتوي نسخة AES-256-GCM مشفرة من إعدادات الحسابات والتوكنات. **مفتاح فك التشفير غير موجود على GitHub** ويظل في `data/secret.key` على الجهاز الأصلي. لا ترفع هذا المفتاح أو تشاركه علنًا.

لاستعادة الإعدادات على جهاز تملكه: انقل `data/secret.key` الأصلي بطريقة خاصة إلى نفس المسار في النسخة الجديدة، ثم شغّل `node scripts/restore-settings.js` قبل تشغيل البرنامج. بدون المفتاح لا يمكن استعادة النسخة. صلاحية التوكنات تظل خاضعة لـGoogle وMeta، وقد تحتاج إعادة ربط Gmail. هذه النسخة لا تحتوي صور البوستات أو سجل الإيميلات.

## Gmail

من «الإعدادات والربط»، أدخل حساب الاستقبال `nuvexars@gmail.com` وعنوان المرسل الحقيقي المستخدم في أتمتة Gemini.

في Google Cloud: فعّل Gmail API، أنشئ OAuth consent screen، أضف حسابك إلى Test users أثناء التجربة، ثم أنشئ OAuth Client من نوع Web application. أضف Redirect URI التالي حرفيًا:

`http://127.0.0.1:3210/auth/google/callback`

احفظ Client ID وClient Secret في الموقع ثم اضغط «ربط Gmail». يتم التحقق أن الحساب الذي اخترته مطابق لحساب الاستقبال. يستخدم التطبيق `gmail.readonly` ولا يعلّم الرسائل مقروءة ولا يعدّلها. قد تنتهي صلاحية Refresh Token في وضع Testing؛ جهّز حالة تطبيق Google المناسبة للاستخدام المستمر.

المزامنة كل دقيقة تستقبل الإيميلات من Inbox بموضوع يحتوي `[NUVEXA]` والمرسل المحدد، من آخر **7 أيام**. تحتفظ قاعدة البيانات بأرقام الرسائل المستقبلة، وتستقبل الرسائل الفائتة عند إعادة التشغيل طالما داخل هذه المدة. الإيميلات ذات JSON غير صالح تظهر في سجل النشاط وتحتاج إرسال نسخة مصححة جديدة. الصور الناقصة تُعرض كمسودة يمكن إصلاحها. الرسائل المتجاهلة لا تُعاد معالجتها تلقائيًا عند تغيير المرسل؛ أعد إرسالها عند الحاجة.

## Facebook

من Meta Developer App جهّز Pages access والتصاريح `pages_show_list`, `pages_read_engagement`, `pages_manage_posts`. استخدم حسابًا له صلاحية إنشاء محتوى الصفحة. احصل على Page ID و**Page Access Token** من `GET /me/accounts?fields=id,name,access_token,tasks` باستخدام User Token المناسب. تأكد من الصلاحيات وانتهاء التوكن عبر Access Token Debugger ومتطلبات App Review حسب تطبيقك.

احفظ Page ID وPage Token في الإعدادات. Graph API الافتراضي `v21.0` حسب الطلب، ويمكن تغييره إلى نسخة مدعومة من إعدادات التطبيق. تحقق من دعم النسخة في حساب Meta. بيانات ربط محفوظة لا تعني أنها اختُبرت مع Meta؛ أول نشر فعلي يحتاج بيانات صالحة.

## الاستخدام

- كل بوست يدخل «بانتظار المراجعة». فحص الصورة تقني؛ لا يتم تقييم صحة الكلام أو تناسقه باستخدام AI.
- استخدم «إضافة بوستات» لاستيراد JSON يدويًا مع صور، حتى قبل ربط Gmail.
- نفس schema السابق: brand، date، posts، post_id، theme، caption، image_url اختياري. Brand يجب أن يكون `NUVEXA PROPERTIES`.
- صور JPG/PNG ثابتة بحد أقصى 8 MiB و10 مليون بكسل. يتم فك الصورة والتحقق منها، إزالة metadata وإعادة ترميزها بصيغتها للنشر. المرفقات المتعددة باسم `post_1.jpg`، `post_2.png` حسب post_id. صورة واحدة تكفي لإيميل يحتوي بوستًا واحدًا.
- Drive: روابط الملفات العامة فقط. صفحات تسجيل الدخول والتحذيرات والمجلدات ليست صورًا صالحة. استخدم مرفقًا إذا تعذر تحميل رابط.
- التعديلات تُحفظ محليًا. «وافق وانشر» يحفظ التعديل ويعرض تأكيدًا أخيرًا، ثم يرسل الصورة والكابشن فورًا إلى صفحة Facebook المحددة. تاريخ JSON بيانات تعريف وليس موعد جدولة.
- المحتوى المكرر يُكتشف باستخدام brand + date + post_id، بما يشمل المنشور والمرفوض. استخدم post_id جديدًا للمحتوى الجديد. التطبيق مخصص لبراند وصفحة واحدة.
- «رفض» لا ينشر؛ يمكن إعادة فتح المرفوض وتعديله لإعادته للمراجعة.
- إذا قبل Facebook الطلب ثم انقطع الاتصال، تصبح الحالة «نتيجة غير مؤكدة» ولا يُعاد النشر تلقائيًا. افحص الصفحة وسجّل رقم الصورة إن نُشرت، أو أكد عدم وجودها لإعادتها للمراجعة. لا تؤكد عدم النشر قبل الفحص.
- استجابة Graph بخطأ 4xx صريح تُسجل «فشل النشر» ويمكن إعادة الموافقة بعد حل السبب. لا توجد إعادة نشر آلية.
- سجل النشاط يعرض عمليات الاستقبال والتعديل والموافقة والنشر والأخطاء. نتيجة النشر تُحفظ مع photo_id وfacebook_post_id إن توفر.

## البيانات المحلية

SQLite والصور في `data/`. الأسرار مشفرة AES-256-GCM ومفتاح التشفير في `data/secret.key`. احفظ المجلد كاملًا في النسخ الاحتياطية؛ من يملك الملفات والمفتاح يستطيع قراءة الأسرار، فاحمِ حساب Windows ومجلد البيانات. لا ترفع `data/` إلى Git أو تشارك نسخه.

الخادم يستمع إلى 127.0.0.1 فقط؛ ليس للاستخدام العام أو عبر الشبكة. تغيير PORT يتطلب تحديث Redirect URI. الطلبات المعدّلة تحتاج Origin محليًا وCSRF token، وروابط الصور لا تستطيع الوصول للشبكة الداخلية. الربط يحتاج الإنترنت وبياناتك الخاصة، ولا توجد كلمات مرور أو توكنات مضمنة.

## التحقق

`npm.cmd test` يختبر parsing، الصور والتكرار، التنافس على النشر، الاحتفاظ بالحالات غير المؤكدة، CSRF، وإلزام الموافقة. اختبارات Facebook تستخدم استجابات وهمية ولا تنشر على الإنترنت. اختبر OAuth والنشر الفعلي بنفسك بعد إدخال بيانات الحسابات.

المراجع: [Google OAuth](https://developers.google.com/identity/protocols/oauth2/web-server)، [Gmail sync](https://developers.google.com/workspace/gmail/api/guides/sync)، [Meta Pages](https://developers.facebook.com/docs/pages-api/).
